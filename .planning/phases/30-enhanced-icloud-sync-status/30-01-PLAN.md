```swift
enum SyncPhase: Equatable {
    case setup
```

**Important design choice:** Keep `.synced` WITHOUT associated values (no Date?, no Int). Store `lastSyncDate`, `lastImportedCount`, and `lastExportedCount` as separate `var` properties on SyncMonitor (not enum associated values). This avoids the Equatable pitfall from research (Pitfall 4) where sub-second timestamp differences cause excessive SwiftUI redraws. The view reads these properties independently.

Add these new properties to SyncMonitor:
```swift

var lastImportedCount: Int = 0
var lastExportedCount: Int = 0
```

  <action>
Replace the existing `handleSyncChange(hasEnded:errorMessage:)` method with a new `handleSyncEvent(_:)` that processes the full `NSPersistentCloudKitContainer.Event` object. Also update the notification observer in `startMonitoring()` to pass the event object directly.

**Updated notification observer in startMonitoring():**
Extract the event in the notification handler and pass it to handleSyncEvent. Use `MainActor.assumeIsolated` since the observer is on `.main` queue.

**New handleSyncEvent method logic:**

1. Guard-extract the event from notification userInfo using `NSPersistentCloudKitContainer.eventNotificationUserInfoKey`.

2. If `event.endDate == nil` (event started):
   - Cancel any pending synced transition.
   - Switch on `event.type`:
     - `.setup`: Set state to `.syncing(phase: .setup)` ONLY if setup has been in-progress for > 2 seconds (per research Pitfall 3). Use a delayed check: store setup start time, and only update state to .setup after 2s delay. If setup completes before 2s, skip showing "Setting up..." entirely.
     - `.import`: Record `preImportItemCount` via `currentItemCount()` (only if not already set for this cycle). Set state to `.syncing(phase: .importing(isInitial: !hasCompletedFirstImport))`.
     - `.export`: Set state to `.syncing(phase: .exporting)`.
     - `@unknown default`: Treat as `.syncing(phase: .importing(isInitial: false))`.

3. If `event.endDate != nil && event.error != nil` (event failed):
   - Cancel pending synced transition.
   - Set state to `.error(friendlyErrorMessage(from: event.error!))`.
   - Log warning with event type and error.

4. If `event.endDate != nil && event.error == nil` (event succeeded):
   - If `.import`: Calculate imported count as `max(0, currentItemCount() - preImportItemCount)`. Add to `lastImportedCount`. Reset `preImportItemCount` to 0. Set `hasCompletedFirstImport = true`.
   - If `.export`: Count local items created since last export using FetchDescriptor with predicate `originDeviceID == DeviceIdentifier.current && timestamp > lastExportEndDate`. Set `lastExportedCount`. Update `lastExportEndDate = event.endDate`.
   - If `.setup`: No count tracking needed.
   - Set `lastSyncDate = event.endDate`.
   - Schedule debounced transition to `.synced` (keep existing 1-second debounce pattern).

**Per CONTEXT.md: Reset counts when a new sync cycle begins.** Detect cycle start: when transitioning from `.synced` (or any non-syncing state) to a syncing state, reset both `lastImportedCount = 0` and `lastExportedCount = 0`.

**Add currentItemCount() helper:**

```swift
private func currentItemCount() -> Int {
    guard let modelContext else { return 0 }
    return (try? modelContext.fetchCount(FetchDescriptor<ClipboardItem>())) ?? 0
}
```

**Add countLocalItemsSince(_:) helper:**
```swift
private func countLocalItemsSince(_ date: Date?) -> Int {
    guard let modelContext else { return 0 }
    let deviceID = DeviceIdentifier.current
    let sinceDate = date ?? .distantPast
    let descriptor = FetchDescriptor<ClipboardItem>(
        predicate: #Predicate { item in
            item.originDeviceID == deviceID && item.timestamp > sinceDate
        }
    )
    return (try? modelContext.fetchCount(descriptor)) ?? 0
}
```
