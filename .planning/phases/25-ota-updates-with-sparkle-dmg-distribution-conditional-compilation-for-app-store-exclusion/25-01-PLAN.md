<task type="auto">
  <name>Task 1: Add Sparkle SPM dependency and xcodegen configVariants to project.yml</name>
  <files>project.yml</files>
  <action>
Modify project.yml to support dual App Store / Sparkle distribution:

1. **Replace the existing `configs` section** (or add if missing) with four explicit configs:
   ```yaml
   configs:
     Debug-AppStore: debug
     Release-AppStore: release
     Debug-Sparkle: debug
     Release-Sparkle: release
   ```

2. **Add Sparkle to the `packages` section:**
   ```yaml
   Sparkle:
     url: https://github.com/sparkle-project/Sparkle
     from: "2.8.0"
   ```

3. **Add `configVariants` under the Pastel target's `scheme`:**
   ```yaml
   scheme:
     configVariants:
       - AppStore
       - Sparkle
   ```
   This generates two schemes: "Pastel AppStore" and "Pastel Sparkle".

4. **Add per-config settings under the Pastel target's `settings.configs`:**
   ```yaml
   configs:
     Debug-Sparkle:
       SWIFT_ACTIVE_COMPILATION_CONDITIONS: "$(inherited) SPARKLE"
       CODE_SIGN_ENTITLEMENTS: Pastel/Resources/Pastel-Sparkle.entitlements
     Release-Sparkle:
       SWIFT_ACTIVE_COMPILATION_CONDITIONS: "$(inherited) SPARKLE"
       CODE_SIGN_ENTITLEMENTS: Pastel/Resources/Pastel-Sparkle.entitlements
   ```
   Do NOT add SPARKLE to AppStore configs. The base CODE_SIGN_ENTITLEMENTS (Pastel.entitlements) applies to AppStore configs via the existing `base` settings.

5. **Add Sparkle to the `dependencies` list:**
   ```yaml
   - package: Sparkle
   ```

6. **Add a postBuildScripts entry** to strip Sparkle from non-Sparkle builds:
   ```yaml
   postBuildScripts:
     - script: |
         if [[ "$CONFIGURATION" == *"Sparkle"* ]]; then
           echo "Sparkle build -- keeping Sparkle.framework"
         else
           echo "App Store build -- removing Sparkle.framework"
           rm -rf "${TARGET_BUILD_DIR}/${FRAMEWORKS_FOLDER_PATH}/Sparkle.framework"
           rm -rf "${TARGET_BUILD_DIR}/${FRAMEWORKS_FOLDER_PATH}/Sparkle_XPCServices.framework" 2>/dev/null || true
         fi
       name: "Strip Sparkle from App Store Builds"
   ```

IMPORTANT: Preserve ALL existing settings (PRODUCT_BUNDLE_IDENTIFIER, MARKETING_VERSION, CURRENT_PROJECT_VERSION, SWIFT_VERSION, INFOPLIST_FILE, CODE_SIGN_ENTITLEMENTS in base, GENERATE_INFOPLIST_FILE, ASSETCATALOG_COMPILER_APPICON_NAME, CODE_SIGN_STYLE, DEVELOPMENT_TEAM, CODE_SIGN_IDENTITY, ENABLE_USER_SCRIPT_SANDBOXING) and ALL existing dependencies (KeyboardShortcuts, LaunchAtLogin, HighlightSwift, CloudKit.framework).
  </action>
  <verify>
Run `cd /Users/phulsechinmay/Desktop/Projects/pastel && xcodegen generate` and confirm it succeeds without errors. Then verify the generated project has both schemes by running `xcodebuild -list` and confirming "Pastel AppStore" and "Pastel Sparkle" appear.
  </verify>
  <done>project.yml defines 4 configs, 2 schemes via configVariants, Sparkle SPM package, SPARKLE compilation condition on Sparkle configs only, separate entitlements path for Sparkle configs, and a post-build strip script. xcodegen generates successfully.</done>
</task>
