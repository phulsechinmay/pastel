<objective>
Eliminate the two biggest sources of panel open lag: (1) replace `appState.itemCount` with `panelActions.showCount` in the `.id()` modifier so that view recreation only happens once on panel open (not on every clipboard capture while hidden), and (2) cache per-card app icon lookups and pre-warm caches during clipboard capture.

Purpose: First-open lag is the most user-visible performance problem. The `.id(itemCount)` pattern triggers view recreation on every clipboard capture even while the panel is hidden, because NSHostingView evaluates body changes regardless of visibility. Switching to `showCount` ensures recreation only happens when the panel actually opens. Caching app icons eliminates redundant disk I/O during scroll.

Output: PanelContentView with showCount-based .id(), cached app icon lookups, and pre-warming of caches during clipboard capture.
</objective>

  **PanelContentView.swift:**
  Replace `appState.itemCount` with `panelActions.showCount` in the `.id()` modifier on FilteredCardListView (line ~118). The `.id()` should contain `panelActions.showCount`, `debouncedSearchText`, and the sorted `selectedLabelIDs` string.

  **Why showCount instead of itemCount:** `@Query` inside NSHostingView/NSPanel does NOT reliably auto-observe new SwiftData insertions — this is a confirmed, consistent issue. The `.id()` refresh mechanism must stay. However, `itemCount` changes on EVERY clipboard capture, triggering view recreation even while the panel is hidden (the NSHostingView is always in the window hierarchy). `showCount` only increments when the panel is shown, so:
  - While panel is hidden: 10 captures = 0 recreations (currently 10)
  - When panel opens: 1 recreation with fresh @Query data
  - Items captured while panel is already open won't appear until next toggle (acceptable — users open to paste, not to watch new items arrive)

  The `.id()` should look like:
  ```swift
  .id("\(panelActions.showCount)\(debouncedSearchText)\(selectedLabelIDsString)")
  ```

  Update the comment to explain: `.id()` uses showCount (not itemCount) to avoid unnecessary recreation while the panel is hidden. @Query re-fetches on panel open via showCount change.

  **NSWorkspace+AppIcon.swift:**
  Add an in-memory cache (dictionary) to the `appIcon(forBundleIdentifier:)` extension. Use a module-level `@MainActor` cache class (or a static dictionary on NSWorkspace extension) keyed by bundle ID string -> NSImage. On cache hit, return immediately without calling `urlForApplication` or `icon(forFile:)`. On cache miss, perform the lookup and store the result.

  Implementation approach: Create an `AppIconCache` class (similar to `AppIconColorService` pattern) as a `@MainActor final class` with `static let shared` and a `private var cache: [String: NSImage]` dictionary. Add a `func icon(forBundleID: String) -> NSImage?` method. Then update the `NSWorkspace.appIcon(forBundleIdentifier:)` extension to delegate to this cache.

  Alternatively, add the cache directly into the NSWorkspace extension using a static property. Either approach works -- the key constraint is that the cache must be @MainActor (NSImage is not Sendable) and persist for the app lifetime.
