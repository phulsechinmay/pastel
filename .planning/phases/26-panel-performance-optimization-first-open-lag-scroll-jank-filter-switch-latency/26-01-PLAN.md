<objective>
Eliminate the two biggest sources of panel open lag: (1) the `.id(appState.itemCount)` modifier that forces full view destruction/recreation every time the panel opens after clipboard captures, and (2) uncached per-card app icon and dominant color computation that fires on every card appearance.

Purpose: First-open lag is the most user-visible performance problem. The `.id()` nuclear recreation is the single largest contributor because it destroys and rebuilds the entire view hierarchy (including all LazyVStack children) on every panel open. Caching app icons eliminates redundant disk I/O during scroll.

Output: PanelContentView without itemCount-triggered recreation, cached app icon lookups, and pre-warming of caches during clipboard capture.
</objective>

If there's any concern, the existing `.onChange(of: panelActions.showCount)` handler already fires on every panel show -- this naturally causes a SwiftUI update cycle that ensures @Query re-evaluates. No additional refresh mechanism is needed.

  Update the comment to explain the new approach: `.id()` only changes on filter parameter changes, not item count. @Query handles new item observation automatically.

  **NSWorkspace+AppIcon.swift:**
  Add an in-memory cache (dictionary) to the `appIcon(forBundleIdentifier:)` extension. Use a module-level `@MainActor` cache class (or a static dictionary on NSWorkspace extension) keyed by bundle ID string -> NSImage. On cache hit, return immediately without calling `urlForApplication` or `icon(forFile:)`. On cache miss, perform the lookup and store the result.

  Implementation approach: Create an `AppIconCache` class (similar to `AppIconColorService` pattern) as a `@MainActor final class` with `static let shared` and a `private var cache: [String: NSImage]` dictionary. Add a `func icon(forBundleID: String) -> NSImage?` method. Then update the `NSWorkspace.appIcon(forBundleIdentifier:)` extension to delegate to this cache.

  Alternatively, add the cache directly into the NSWorkspace extension using a static property. Either approach works -- the key constraint is that the cache must be @MainActor (NSImage is not Sendable) and persist for the app lifetime.

  **ClipboardMonitor.swift:**
  After a new ClipboardItem is successfully inserted into SwiftData (i.e., after the `modelContext.insert(item)` + save), pre-warm both the app icon cache and the dominant color cache for the item's source app bundle ID.

  Add a call like:
  ```swift
  // Pre-warm caches so panel open is instant
  if let bundleID = item.sourceAppBundleID {
      _ = AppIconCache.shared.icon(forBundleID: bundleID)  // or however the cache is accessed
      _ = AppIconColorService.shared.dominantColor(forBundleID: bundleID)
  }
  ```

  This MUST happen on the main thread (both services are @MainActor). Since ClipboardMonitor already runs its insert on the main thread, this is naturally safe.

  CRITICAL: This must ONLY read bundle info and compute colors. It must NOT touch NSPasteboard or activate any application. The pre-warming code should be placed AFTER the clipboard monitoring pause/resume logic to avoid interfering with self-paste loop protection.

  **AppState.swift:**
  No changes needed -- the `onItemCountChanged` callback already propagates from ClipboardMonitor to AppState. The pre-warming happens in ClipboardMonitor before the callback fires.

  If AppIconCache is a new class (from Task 1), ensure it is imported/accessible from ClipboardMonitor.swift.
