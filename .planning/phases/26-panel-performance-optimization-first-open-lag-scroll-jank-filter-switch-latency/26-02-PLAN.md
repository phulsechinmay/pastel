<objective>
Memoize the `filteredItems` computed property and add display-level pagination to bound the number of cards rendered at any time. This eliminates O(n) filtering on every SwiftUI body evaluation and ensures the panel renders quickly regardless of total clipboard history size.

Purpose: The `filteredItems` computed property iterates ALL queried items (sync filtering + label filtering) on every body evaluation -- including during scroll events that trigger any state change. With 500+ items, this creates measurable jank. Display pagination ensures only 50 items are rendered initially, with more loaded on-demand.

Output: Memoized filteredItems with onChange-based recomputation, and display pagination with automatic load-more.
</objective>

  **Convert filteredItems from computed property to @State with onChange-based updates:**

  1. Replace the `private var filteredItems: [ClipboardItem]` computed property with:
     - A private function `computeFilteredItems(from items: [ClipboardItem]) -> [ClipboardItem]` that contains the same sync filtering + label filtering logic
     - A `@State private var filteredItems: [ClipboardItem] = []` stored property

  2. Add `.onChange(of: items)` and `.onChange(of: selectedLabelIDs)` modifiers (or combine them into `.onAppear` + `.onChange`) that call `filteredItems = computeFilteredItems(from: items)`. Also add `.onAppear` to set the initial value.

     Note on `.onChange(of: items)`: SwiftData @Query arrays conform to Equatable, so onChange will fire when items change. However, if this doesn't work reliably (because SwiftData arrays may mutate in-place), use `.onChange(of: items.count)` as a proxy and also trigger on `.onAppear`.

  3. When `selectedLabelIDs` changes, also reset `displayLimit` back to the initial page size (50) so the user sees fresh results from the top.

  **Add display-level pagination:**

  4. Add state: `@State private var displayLimit: Int = 50` and a constant `private let pageSize: Int = 50`.

  5. Add a computed property `private var visibleItems: [ClipboardItem]` that returns `Array(filteredItems.prefix(displayLimit))`.

  6. Replace ALL references to `filteredItems` in the body/ForEach/key handlers with `visibleItems` -- EXCEPT for the total count checks. Specifically:
     - `ForEach(Array(visibleItems.enumerated()), id: \.element.id)` for rendering
     - `visibleItems.isEmpty` for empty state check
     - `visibleItems[index]` for keyboard paste handlers
     - `visibleItems.count` for bounds checking in moveSelection and key handlers

  7. In the `cardView(for:at:)` helper, add an `.onAppear` modifier that checks if the card's index is within 10 of the displayLimit and triggers loading more:
     ```swift
     .onAppear {
         if index >= displayLimit - 10 && displayLimit < filteredItems.count {
             displayLimit += pageSize
         }
     }
     ```

  8. Reset `displayLimit = 50` in the `.onAppear` of the main view (alongside `selectedIndex = nil`), and when `selectedLabelIDs` changes.

  **Important constraints:**
  - The `ForEach` MUST use `\.element.id` (ClipboardItem's persistent ID) as the identity, NOT the enumeration index. The current code already does this: `id: \.element.id`. Keep it.
  - The `.id(index)` on each card (line ~297) is used for ScrollViewReader. This uses the enumeration index which is fine for scrolling as long as selectedIndex maps to the visible array.
  - Quick paste hotkeys (Cmd+1-9) use `filteredItems[index]` -- change to `visibleItems[index]`. Since quick paste only uses indices 0-8, pagination (minimum 50) will never truncate these.
  - `moveSelection` uses `filteredItems.count` for bounds -- change to `visibleItems.count`.
