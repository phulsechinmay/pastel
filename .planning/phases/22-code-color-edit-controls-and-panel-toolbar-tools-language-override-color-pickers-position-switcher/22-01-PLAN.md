  <name>Task 1: Add language override and removal controls to EditItemView for code items</name>
  <files>
    Pastel/Views/Panel/EditItemView.swift
    Pastel/Services/CodeDetectionService.swift
  </files>
  <action>
  **EditItemView.swift changes:**

  Add a conditional `CodeEditSection` below the label section in EditItemView, shown only when `item.type == .code` OR when the item was previously code (to allow re-adding).

  The `CodeEditSection` should contain:

  1. **Language Picker** -- A `Picker` (or `Menu`) labeled "Language" showing:
     - Current detected language (if any) as the selected value
     - A curated list of ~25 popular languages as options. Use a static array of `(display: String, id: String)` tuples where `id` is the highlight.js alias (lowercase) matching what `CodeDetectionService.languageHint()` stores. Include: swift, python, javascript, typescript, java, kotlin, go, rust, ruby, php, c, cpp, csharp, objectivec, html, css, bash, sql, json, yaml, xml, markdown, r, scala, perl, lua, dart, elixir, haskell, dockerfile, graphql, powershell.
     - The picker selection should be a `Binding<String?>` where `nil` means "Auto-detect" (original behavior).
     - On change: set `item.detectedLanguage = selectedLanguage`. If selecting a specific language on a non-code item, also set `item.contentType = ContentType.code.rawValue`. Evict the HighlightCache entry for `item.contentHash` so CodeCardView re-highlights on next render.

  2. **"Remove code detection" Button** -- A destructive-style button that:
     - Sets `item.detectedLanguage = nil`
     - Sets `item.contentType = ContentType.text.rawValue` (or `ContentType.richText.rawValue` if `item.rtfData != nil`)
     - Evicts the HighlightCache entry for `item.contentHash`
     - The button text should be "Remove code formatting" in red/destructive style.

  **CodeDetectionService.swift (HighlightCache) changes:**

  Add an `evict(_ hash: String)` method to the `HighlightCache` actor that removes a specific entry from `cache` and `insertionOrder`. This is needed so that when the user changes the language, the stale cached highlighting is cleared.

  **CodeCardView.swift changes:**

  Update the `.task(id:)` modifier to include `item.detectedLanguage` in the task ID so that when the language changes, the view re-runs `loadHighlighting()`. Change from `.task(id: item.contentHash)` to `.task(id: "\(item.contentHash)_\(item.detectedLanguage ?? "")")`.
  </action>
  <verify>
  Build the project with `xcodebuild`. Verify:
  - EditItemView compiles with the new CodeEditSection
  - HighlightCache has the evict method
  - CodeCardView task ID includes detectedLanguage
  </verify>
  <done>
  Code items show a language picker in the edit modal with ~25+ language options. Changing the language updates item.detectedLanguage, evicts the highlight cache, and the card re-highlights with the new language. "Remove code formatting" button reverts the item to plain text type, clearing language and contentType.
  </done>
</task>

<task type="auto">
  <name>Task 2: Add color picker controls to EditItemView for color items</name>
  <files>
    Pastel/Views/Panel/EditItemView.swift

  <action>
  Add a conditional `ColorEditSection` below the CodeEditSection (or label section if not code) in EditItemView, shown only when `item.type == .color`.

  The `ColorEditSection` should contain:

  1. **SwiftUI ColorPicker** -- A `ColorPicker` labeled "Color" bound to a `@State private var editColor: Color` property.
     - Initialize `editColor` in `.onAppear` by parsing `item.detectedColorHex` into a `Color`. If `detectedColorHex` is nil or unparseable, default to `.white`.
     - Set `supportsOpacity: false` (hex colors are opaque).
     - On `.onChange(of: editColor)`: convert the `Color` to `NSColor`, then to sRGB color space via `color.usingColorSpace(.sRGB)`, extract RGB components, format as uppercase hex string (without `#` prefix, matching existing `detectedColorHex` format -- check ClipboardItem to confirm format), and update `item.detectedColorHex`.

  2. **Hex display** -- Show the current hex value as a read-only text label below the picker (e.g., "#FF5733") so the user can see the exact value.

  **Important:** Check the format of `detectedColorHex` in `ColorDetectionService.swift` to ensure the edit modal writes back in the same format. The existing format stores hex WITHOUT the `#` prefix (e.g., "FF5733"), so write back in that same format.

  **NSColor to Color conversion helper:** Create a small private helper that converts a hex string (6 chars, no #) to a SwiftUI `Color` for initializing the picker.
  </action>
  <verify>
  Build the project. Verify ColorEditSection only appears for color-type items and that the ColorPicker binding compiles correctly.
  </verify>

  </done>
