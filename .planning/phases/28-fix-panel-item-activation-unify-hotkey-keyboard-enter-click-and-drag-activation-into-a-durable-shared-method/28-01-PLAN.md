<objective>
Fix broken keyboard activation in the panel by migrating Enter, Cmd+1-9, and Cmd+Shift+1-9 handlers from broken SwiftUI `.onKeyPress` to the proven NSEvent local monitor pattern already used for arrow keys. Remove the three broken `.onKeyPress` handlers.

Purpose: Enter-to-paste and quick paste hotkeys (Cmd+1-9, Cmd+Shift+1-9) never fire because the `.focusable()` Group in FilteredCardListView doesn't reliably receive SwiftUI keyboard focus in the NSPanel context. Arrow keys work because they use NSEvent local monitor. This plan extends that working pattern to all activation keys.

Output: FilteredCardListView.swift with unified `installKeyboardMonitor()` handling arrows + Enter + Cmd+digits, three broken `.onKeyPress` handlers removed, type-to-search `.onKeyPress` kept.
</objective>

**1. Add static digit key code map** (add as a static property on the struct, before `body`):
```swift
private static let digitKeyCodeMap: [UInt16: Int] = [
    0x12: 1,  // kVK_ANSI_1
    0x13: 2,  // kVK_ANSI_2
    0x14: 3,  // kVK_ANSI_3
    0x15: 4,  // kVK_ANSI_4
    0x17: 5,  // kVK_ANSI_5
    0x16: 6,  // kVK_ANSI_6
    0x1A: 7,  // kVK_ANSI_7
    0x1C: 8,  // kVK_ANSI_8
    0x19: 9,  // kVK_ANSI_9
]
```

**2. Rename `installArrowKeyMonitor()` to `installKeyboardMonitor()`** and extend the `default:` case to handle Enter and Cmd+digit keys:

- **Enter/Return handling** (add as a new case before `default:`):
  - Key codes: `case 0x24, 0x4C:` (Return + Keypad Enter)
  - If `selectedIndex` is valid and within `visibleItems.count`:
    - Check `event.modifierFlags.contains(.shift)` -- if true, call `onPastePlainText(visibleItems[index])`
    - Otherwise call `onPaste(visibleItems[index])`
    - Return `nil` (consumed)
  - If no valid selection, return `event` (pass through)

- **Cmd+digit handling** (replace `default: return event` with):
  - Check `event.modifierFlags.contains(.command)` AND `Self.digitKeyCodeMap[event.keyCode]` returns a digit
  - Guard `quickPasteEnabled` else return `event`
  - Convert digit to 0-based index (`digit - 1`)
  - Guard `index < visibleItems.count` else return `event`
  - Check `event.modifierFlags.contains(.shift)` -- if true, call `onPastePlainText(visibleItems[index])`
  - Otherwise call `onPaste(visibleItems[index])`
  - Return `nil` (consumed)
  - If not a Cmd+digit combo, return `event` (pass through)

**3. Update the `installArrowKeyMonitor()` call site** in `.onAppear` to use the new name `installKeyboardMonitor()`.

**4. Update the doc comment** on the monitor function from "Install NSEvent local monitor for arrow key handling" to "Install NSEvent local monitor for keyboard handling (arrows, Enter, Cmd+digit activation)".

**5. Remove the three broken `.onKeyPress` handlers** (lines 189-233 in the current file):
- Remove `.onKeyPress(keys: [.return])` handler (Enter/Return)
- Remove `.onKeyPress(characters: .decimalDigits)` handler (Cmd+1-9)
- Remove `.onKeyPress(characters: CharacterSet(charactersIn: "!@#$%^&*("))` handler (Cmd+Shift+1-9)
- **Keep** the `.onKeyPress(characters: .alphanumerics.union(.punctuationCharacters))` handler (type-to-search) -- it is a different category per user decision

**6. Keep `.focusable()` and `.focusEffectDisabled()`** -- they are still needed for the type-to-search `.onKeyPress` handler and for `.focused($panelFocus, .cardList)` targeting in PanelContentView.

**Important implementation notes:**
- Do NOT use `event.characters` for digit detection when Cmd is held -- macOS modifies characters with Cmd modifier. Use `event.keyCode` which is always the physical key.
- Return `nil` for consumed events, `event` for pass-through. Returning `event` passes it to other monitors (PanelController's Escape handler).
- The existing arrow key handler accesses `self.selectedIndex`, `self.visibleItems`, `self.quickPasteEnabled` through the closure and works correctly -- use the same pattern for Enter and digits.
- The existing `isShiftHeld` property is for UI rendering (Shift+double-click visual state) and is NOT used for keyboard modifier detection. The NSEvent handler uses `event.modifierFlags.contains(.shift)` directly.
